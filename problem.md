GrackleDocs users need a simple way to review accessibility issues identified in digital documents and web-based content, such as PDFs, web pages, forms, and office documents, and track their remediation progress.

Build a small React application that supports this workflow.

As part of the exercise, use AI tools and any other appropriate resources to research common accessibility issues and create a small, representative dataset for your application. You should decide what information each issue should contain, how issues should be categorized, and how remediation progress should be represented.

At a minimum, users should be able to:
- Review identified accessibility issues
- Find or narrow down relevant issues
- Open an issue to understand it in more detail
- Track or update its remediation progress

The rest of the product and interaction design is intentionally open-ended. You should determine the structure, terminology, workflows, and presentation you believe would best support the user.

Include reasonable handling for loading, empty, and error states. You may simulate
asynchronous operations using timers, promises, local data, or a lightweight mock API.

A production backend is not required.
